# clear-view

把一段材料快速变成「现在是什么情况」：先结构化文字，再给默认可视 HTML。不站队、不编造原文没有的事实。

## 核心原则

- **双交付固定**：每次都给 **文字版 + 可视版**（除非用户明确只要其中一种）。
- **最短够用**：栏目按材料类型取舍，没有的不硬凑。
- **忠实原文**：观点归说话人；不确定就标「原文未明」；禁止补戏。

## 何时用 / 不用

**用：** 对话糊、长文难扫、教程目录不清、产品功能散、多人争论同异难辨、用户说「讲清楚 / 画清楚 / 理清一下」。

**不用：** 只要一句摘要；只要改代码/实现；只要原文翻译；开发架构专用可视化且用户点名 show-me 原版流程。

## 交付契约

### 1) 文字版（聊天里直接给）

按材料选用下列栏目，**有则写、无则跳过**，标题保持短：

| 栏目 | 何时出现 |
|---|---|
| 主题 | 几乎总有：一句话 |
| 现在是什么情况 | 一句话现状小结（放靠前） |
| 结构 / 流程 / 目录 | 教程、长文、说明文档 |
| 功能 / 能力清单 | 产品说明 |
| 各方说了什么 | 对话、会议、多人线程（按人分点） |
| 话题线 | 同时在谈 2+ 话题时：每条话题一行 |
| 共同点 | 多方有交集时 |
| 差异 / 争论点 | 有分歧或未决时 |
| 未决 / 待澄清 | 原文含糊、指代不清时 |
| 小结 | 3 条以内，不重复「现在是什么情况」 |

文字版要求：结论先行；列表优于长段；关键原话可短引，不整段粘贴。

### 2) 可视版（默认轻量信息图 HTML）

- **默认**：写一份自包含 HTML（单文件、可离线打开），用简单图示讲清关系/流程/发言，而不是再堆一段散文。
- **人物**：多人对话时用简洁角色块或小人标记区分说话人（颜色/标签固定，图例写清是谁）。
- **话题分叉**：多话题时分栏或分叉线，标出共同节点与分叉点。
- **流程 / 架构**：步骤用横向或纵向流程；系统关系用简单框线。
- **不够用时再加**：Mermaid、调用树、文件树、diff —— 作为 HTML 内嵌或文字版附录，不替代默认 HTML。
- **交付**：把 HTML 文件交给用户可打开（附件或等价展示）；文件名 `clear-view-{short-slug}.html`。
- **观感**：字号可读、对比足够、移动端可扫；少装饰、无无关动画；标签用原文语言（用户用中文则中文）。

## 执行步骤

1. 确认材料范围（用户粘贴 / 链接 / 指定段落）；材料过长先分段，但结论仍要覆盖整体「现在是什么情况」。
2. 判定类型：对话 | 文章/论文 | 教程 | 产品说明 | 混合。
3. 抽出：主题、说话人、话题线、同异、未决——只依据原文。
4. 输出文字版（按上表栏目）。
5. 生成默认可视 HTML 并交付；若用户只要文字或只要图，遵守其选择。
6. 若原文关键处含糊：在「未决」写明，并在图上用虚线/问号标出，不要猜成实线结论。

## 材料类型速查

- **对话 / 争论**：人 → 各自主张 → 争论焦点 → 同异 → 现状小结；HTML 用角色 + 话题分叉。
- **文章 / 论文**：问题 → 论点/证据结构 → 结论；HTML 用论证结构或章节地图。
- **教程**：目标 → 步骤/模块 → 你会学到什么；HTML 用步骤流程。
- **产品说明**：产品是什么 → 功能清单 → 谁适用；HTML 用功能地图。

## 常见失误

| 失误 | 改正 |
|---|---|
| 只给摘要长文，没有结构栏目 | 按契约出文字版栏目 |
| 只有 Mermaid、没有 HTML | 默认必须先有轻量 HTML |
| 把推断写成事实 | 标「原文未明」或放入未决 |
| 为「好看」堆动画/大段装饰文案 | 删掉，只留帮助理解的标签与关系 |
| 小人好看但分不清是谁 | 固定颜色+图例，标签写名字/角色 |
| 多话题揉成一条时间线 | 拆话题线，再标交叉点 |

## 红旗 — 停下改正

- 准备只交一种交付物（用户没说只要一种）
- 图上有原文没有的结论
- 用开发 show-me 的代码树代替对话/文章澄清
- 把「清晰呈现」做成二次创作或立场站队
